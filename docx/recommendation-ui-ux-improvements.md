# 추천 화면 UI/UX 개선 작업 정리

- 문서 작성일: 2026-11-20
- 대상: 추천 화면의 **계산 근거와 한계 펼치기** 영역
- 구현 파일: [WarehouseRecommendationView.cs](../Assets/Scripts/UI/WarehouseRecommendationView.cs)
- 구현 위치: `Details()`

## 개선 목적

펼치기 영역에 전략별 수치, 수식, 입력 조건, 가정과 주의사항이 길게 나열되어 핵심을 읽기 어려웠습니다. 계산 근거는 유지하면서 사용자가 추천 이유와 예상 수량, 한계를 빠르게 확인할 수 있도록 정리했습니다.

최종 요청은 **계산 근거를 포함한 10~15줄 분량**입니다. 현재는 소제목을 포함해 명시적 줄바꿈 기준 **14줄**로 구성했습니다. 화면 폭과 숫자 길이에 따라 실제 표시 줄 수는 늘어날 수 있습니다.

## 최종 화면 구성

| 구역 | 줄 수 | 내용 |
| --- | ---: | --- |
| 선정 기준 | 3 | 제목, 수량·바닥 활용률·높이의 우선순위, 조건 검토 |
| 계산 근거 | 7 | 제목, 한 층 수량, 팔레트당 수량, 높이, 하중, 한도, 창고 전체 예상량 |
| 가정과 한계 | 4 | 제목, 창고 형상·제외 면적, 무게 기준, 현장 확인 사항 |
| 합계 | 14 | 소제목 3줄과 본문 11줄 |

### 표시 예시

아래 숫자는 이전 UI 검증에 사용한 예시이며, 화면에는 현재 입력과 추천안의 실제 계산 결과가 표시됩니다.

```text
선정 기준
수량 최대 → 바닥 활용률 → 낮은 높이
확인 가능한 높이·하중·경계 조건 검토
계산 근거
한 층: 가로 3 × 세로 2 = 6개
팔레트당: 6개 × 5층 = 30개
높이(m): 0.15 + 5 × 0.315 ≈ 1.73
하중(kg): 30 × 3.008 ≈ 90.24
한도: 높이 1.80m · 화물 1,000kg
창고: 308팔레트 × 30개 ≈ 9,240개
가정과 한계
정사각형 창고 · 통로·설비 20% 제외
분류별 기준 무게 사용, 실제 무게 확인
현장 배치·포장·고정·안전성 별도 확인
```

## 주요 변경 사항

- A/B/C 전략별 상세 수치를 반복하던 구성을 추천안 중심으로 정리했습니다.
- 긴 문장 대신 짧은 항목과 수식을 사용했습니다.
- 선정 기준, 계산 근거, 가정과 한계를 굵은 소제목으로 구분했습니다.
- 수량이 산출되는 과정을 **한 층 → 팔레트당 → 창고 전체** 순서로 표시했습니다.
- 높이에 팔레트 높이가 포함되고, 하중에 기준 무게가 사용된다는 점을 드러냈습니다.
- 화면의 계산 결과는 공통 계산기에서 받은 값을 사용합니다.

### 상태별 표시

- **무게가 등록된 경우:** 수량 × 개당 기준 무게로 하중을 표시하고, 실제 무게 확인을 안내합니다.
- **무게가 누락된 경우:** 하중 확인 필요와 조건부 예상치라는 안내를 표시합니다.
- **추천안이 없는 경우:** 수량·높이·하중의 일반 계산식을 표시하고, 전체 예상량은 추천 가능한 배치가 없다고 안내합니다.

### 펼치기·접기 동작

- 상세 영역은 처음에 접힌 상태입니다.
- 버튼을 누르면 상세 영역을 표시하고 문구를 ‘계산 근거와 한계 접기’로 바꿉니다.
- 다시 누르면 상세 영역을 숨기고 ‘계산 근거와 한계 펼치기’로 되돌립니다.
- 상태 변경 시 레이아웃을 다시 계산해 내용 높이와 스크롤 영역을 갱신합니다.

## 요청 반영 과정

1. 긴 원문에서 반복 수치와 장문 설명을 줄여 핵심 항목 중심으로 정리했습니다.
2. ‘아주 짧게’ 요청에 따라 기준·예상량·하중·한계의 네 줄로 축약했습니다.
3. 이후 ‘계산 근거를 포함해 10~15줄’ 요청을 반영해 현재의 14줄 구성으로 조정했습니다.

현재 적용된 결과는 마지막 단계의 14줄 구성입니다.
